# AINET Spec v1.0 — 让全网 AI 助手都能与你协作
# AINET Specification v1.0 — Collaboration Page for the Agentic Web

> **版本**：v1.0——版本从 AINET 传输协议 v0.2（2026-03-29，AINET-INSTRUCTIONS）延续，业务协作层加入后正式化为 1.0
> **状态**：已发布（公开征集反馈） | **维护**：51Toko（首个参考实现方） | **仓库**：github.com/joezhouai/ainet
> **一句话**：AINET 是一个轻量开放规范——服务方发布一个**协作页（Collab Page）**，任何用户的任何 AI 助手读到它，即可代表服务方完成前端协作流程：身份判定 → 需求采集 → 结构化投递 → 预期管理 → 方向转介。
> **它解决什么**：Agentic Web 里，AI 怎么知道怎么"使用"一个服务？重协议（MCP/A2A/NLIP）需要开发端点，交易协议（ACP/UCP/AP2）只管标品结账——**非标服务的 AI 前端**是空白。AINET 用"自然语言协作页"填补：接入成本从开发成本降为写作成本。

---

## 0. 设计原则

1. **自然语言即协议**：协作页是人读+AI 执行的双态文档，零开发；
2. **平台无关**：不绑定任何 AI 引擎/厂商/框架；
3. **用户主权**：用户显式授权触发；判断与决策归用户；
4. **诚实边界**：能力、数据性质、交付周期、不承诺事项必须如实声明——AI 助手须如实转述，不允许幻觉背书；
5. **兼容喂料**：不否定传统渠道，AI 协作是服务前台的增量入口。

## 1. 协作页必备五节（服务方 MUST）

### 1.1 入口与触发词
- 页面路径建议：`/collab`（推荐）或 `/ai/`；
- 必须声明触发词（如"开始协作"）并说明**为什么需要显式触发**；
- ⚠️ **触发指令必须由用户消息携带完整协作页 URL**（如 `https://<域名>/collab/，开始协作`）——URL 完整度与执行质量严格正相关（实测：裸域名 2/5 → scheme 域名 4/5 → 协作页 URL 5/5，见 §5）。

### 1.2 身份与方向判定
- 显式排他：本入口只受理什么（服务/方向/用户身份），一句话说死；
- 不受理的方向必须给出对应入口完整 URL；
- 禁止"同一入口什么都收"。

### 1.3 通道与降级
- 列出全部通道及其**真实状态**（可用/需申请/未开放），状态表述防跳读；
- 必须提供零门槛降级链：MCP/API（需开通）→ 邮件（现即可用）→ 人工；
- AI 无发信能力时的标准动作：完整结构化正文交用户复制发送（不得代发、不得缩写成摘要）。

### 1.4 需求采集规范
- 一次问齐：必填与选填分组，选填不阻塞；
- 字段收齐后立即进入投递步骤，不停滞；
- 描述质量与结果质量正比关系须明示。

### 1.5 边界与预期管理
- 数据性质（如"历史记录非实时信号"）、判断与决策归属（如"跟进与成交由用户完成"）、协作模式（异步/回执/交付周期）；
- 以上 AI 助手必须如实转述，转述失真即违规。

## 2. 引擎行为约定（AI 助手侧）

### 2.1 引擎前置能力
- **网页获取能力（联网检索或 URL 打开）是硬前提**——无工具引擎应诚实告知用户（不假装协作），并指出协作页 URL 供用户手动访问。

### 2.2 两型合规路径
- **轻执行型**：读到协作页 + 用户带 URL 指令 → 直接执行流程；
- **强安全型**：将协作页视为网页指令而拦截 → **向用户请求确认** → 授权后执行（拦截是合规行为，静默拒绝不是）。

### 2.3 禁止行为
- 未读取协作页而声称"已按其执行"（伪合规）；
- 收集完成后停滞、不进入投递；
- 幻觉式承诺（代表服务方保证结果/夸大能力）；
- 协作页静默当普通文章摘要而不向用户提示协作可能性；
- 混淆方向（A 方向需求提交到 B 方向入口）。

## 3. 用户侧规则
- 指令**必须包含协作页完整 URL**：`https://<域名>/collab/，开始协作`（英文 `https://<域名>/collab/, start collaboration`）；
- 域名裸指令不推荐（可发现性实测仅 1/3 引擎自主找到协作页）；
- 强安全型引擎请求授权确认时，用户应显式回答。

## 4. 版本化
- 协作页必须标注版本（`ai_protocol_version`）；
- 服务方按实测持续迭代：每次引擎失败案例 → 防呆修订 → 版本递增 + 变更记录。

## 6. 与其他标准的关系

| 标准 | 层级 | 与 AINET 关系 |
|---|---|---|
| MCP / A2A / NLIP(ECMA-430) | agent 间消息互操作（重协议） | 前置互补：协作页可声明"MCP 通道开通后使用" |
| ACP / UCP / AP2 | 交易结账（commerce） | 分工：他们管标品交易，AINET 管非标服务协作 |
| llms.txt | 站点索引 | 协作页应在 llms.txt 登记（可发现性） |
| AGENTS.md | 编程域协作说明 | 同思路在编程域；AINET 是商业服务域 |
